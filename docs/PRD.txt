1. Executive Summary
MyLib is a modern, AI-powered personal library manager transitioning from a monolithic Vanilla JS SPA into a professional, scalable React application. It combines the utility of a personal catalog (Libib) with the social discovery of Goodreads, wrapped in a modern, Instagram-style UX.

Key differentiators:

Granular Privacy: Users control exactly what the world sees.

AI Librarian: Personalized insights, metadata fixing, voice interaction.

Social Profiles: Custom URLs (mylib.softrly.com/u/username).

Platform Admin: A dedicated control room for the site owner.

Preserved Legacy Features: Every single feature from v1.0 is retained, but refactored into modern React patterns (Hooks, Context, React Query).

2. Target Audience & User Roles
The Guest (Unauthenticated): Can view the landing page, browse public user profiles, and read public reviews.

The Reader (Authenticated): Manages their own library, sets privacy, uses AI features, and interacts with the community.

The Admin (Site Owner): Full control over platform settings, user management, content moderation, and feature flags.

3. Technical Architecture
Frontend: React 18+ (Vite), TypeScript (Strict Mode), React Router v6.

Borrowing (Loan Manager):

Borrow requests, owner decisions, confirmed physical handovers, active loans, and returns are distinct states. Owner acceptance reserves the book but does not mark it lent; only the borrower confirming receipt creates an active loan. The borrower requests return confirmation, and the owner confirms the return. Returned loan records are retained as history.

Loan records are the source of truth for lending relationships. Books may keep synchronized borrowedBy, borrowDate, borrowHistory, borrowStatus, borrowRequestId, and activeLoanId fields for rendering and availability. Loan numbers use the "Loan #" label and are allocated from a yearly counter.

Borrow-request privacy is configurable as None, Collaborators, Collaborators & Followers, or Any User (default: Collaborators). Requesters must provide a contract number and address in private Settings data. These details are never copied to requests; an owner may explicitly share their phone/address with the requester after accepting.

Insights distinguishes active loans, waiting handovers, return confirmations, and returned history. Owners can send rate-limited return reminders. Loan parties can navigate to one another's public profiles.

5. Data Model (Firestore Schema)
users/{uid}: uid, username, email, bio, avatarUrl, role (user/admin), plan (free/pro), privacySettings (map), totalBooksCount, completedBooksCount, joinedAt.

users/{uid}/private/data: email, phoneNumber, address, contractNumber, lastAIAnalysis, lastAIAnalysisDate.

userLookup/{email}: uid (maps email to uid).

partnerships/{uidA_uidB}: userId1, userId2, initiatorId, status, user1Unsubscribed, user2Unsubscribed, allowAddBooks, grantedBy.

collaborationRequests/{uidA_uidB}: fromUserId, fromEmail, fromName, toUserId, toEmail, status (pending, accepted, rejected, cancelled).

books/{id}: userId, title, author, isbn, coverUrl, thumbnail, description, price, purchaseDate, tags (array), genres (array), categories (array), shelfId, borrowedBy, borrowDate, borrowHistory (array), borrowStatus, borrowRequestId, activeLoanId, highlights (array), copyType, gifterName, source, averageRating, ratingCount, createdAt, updatedAt, addedBy.

books/{id}/readingStatus/{uid}: userId, status (want_to_read, reading, finished), rating, progress, comment, isWishlist, isFavorite, updatedAt, highlights (user-specific).

shelves/{id}: userId, name, isPublic, createdAt.

activityFeed/{id}: type, userId, userName, libraryId, timestamp, bookId, bookTitle, addedTo, status, rating, comment, text, recipientId, targetUserId, borrowedBy, message.

bookRequests/{id}: fromUserId, toUserId, bookId, bookTitle, requesterName, requesterUsername, ownerName, ownerUsername, status (pending, accepted_waiting_confirmation, rejected, cancelled, active), contactInfoShared, optional owner contact fields only after explicit sharing, lifecycle timestamps.

loans/{requestId}: loanNumber, bookId, bookTitle, owner and borrower identities, requestId, status (active, return_pending_confirmation, returned), requestedAt, acceptedAt, confirmedAt, returnedAt, lastReminderAt.

loanCounters/{year}: sequence, lastRequestId, updatedAt.

reviews/{id}: userId, userName, bookTitle, author, category, body, rating, likesCount, commentsCount, createdAt, updatedAt, reported (boolean).

reviews/{id}/likes/{uid}: userId, createdAt.

reviews/{id}/comments/{id}: userId, userName, body, createdAt.

reports/{id}: reporterId, targetType (review/comment/user), targetId, reason, status (pending, resolved), createdAt.

adminConfig/{id}: featureFlags, landingPageContent, systemAISettings.

7. Security & Firestore Rules (Updated)
Books: Readable by owner or active partner. Created by owner or partner with valid grant. Schema-validated.

Reading Status: Readable only by its own user (strict rule).

Users & UserLookup: Readable by any signed-in user. Bounded list queries.

Reviews/Comments/Likes: Author-owned.

Like Counts: Checked against the like doc to prevent forgery.

Comment Count Forgery: Fixed in the new app using Cloud Functions or stricter rules to prevent forged commentsCount.

AI API Keys: Stored securely in sessionStorage, text clarified in UI. Never logged to Firestore.
